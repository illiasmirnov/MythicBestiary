📖 Опис

Про проєкт

Mythic Bestiary — це навчальний вебзастосунок, який моделює електронний бестіарій. У системі зберігаються дані про міфічних істот: назва, категорія, опис, походження, здібності, слабкості, рівень небезпеки та місця існування.

Основна частина проєкту побудована на ASP.NET Core Razor Pages. Для доступу до даних використано окремий сервісний шар і репозиторій, а для передавання даних між шарами — DTO-моделі. Такий підхід робить код зрозумілішим і зручнішим для подальшого розширення.

🏗️ Архітектура

Структура застосунку

🗄️

Data

Містить `MongoDbContext`, `MongoDbSettings` і `SeedData`. Цей рівень відповідає за підключення до MongoDB та початкове наповнення бази даних.

📦

DTOs

DTO-моделі використовуються для створення, оновлення, перегляду й відображення списку істот без прямої прив’язки інтерфейсу до моделі бази даних.

🧭

Pages/Creatures

Razor Pages реалізують GUI для CRUD-операцій: створення, перегляду, редагування та видалення записів про міфічних істот.

✅

Validation

`CreatureValidator` має перевіряти назву, опис, категорію, походження, рівень небезпеки, здібності, слабкості та коректність географічних даних.

🔁

Repositories

Репозиторій і сервісний шар відокремлюють логіку доступу до даних від сторінок інтерфейсу та спрощують тестування.

🛡️

Middleware та Logging

Middleware відповідає за централізовану обробку помилок, а логування допомагає відстежувати HTTP-запити та роботу системи.

🗺️ Геодані

Як проєкт демонструє роботу з геоданими

Для відповідності першій методичці записи про істот мають містити географічну інформацію: координати місця існування, назву регіону та тип середовища. У MongoDB це доцільно зберігати у форматі GeoJSON. 

{
  "habitat": "Вулканічні нагір’я",
  "location": {
    "type": "Point",
    "coordinates": [36.2304, 49.9935]
  }
}

Така структура дозволяє надалі реалізувати пошук істот поблизу певної точки, фільтрацію за регіоном і демонстрацію геоіндексів MongoDB.

🎓 Відповідність

Зв’язок із вимогами методичок

Методичка 1

Проєкт відповідає вимозі створення клієнтського застосунку з MongoDB, GUI/WUI та CRUD-операціями. Для повної відповідності потрібно показати роботу з геоданими через GeoJSON і геоіндекси.

Методичка 2

Поточна структура підтримує Razor Pages, валідацію, Dependency Injection, логування та патерн репозиторію. Для повної відповідності другій частині потрібно додати SQL Server, EF Core, Code-First і міграції.

Рекомендований варіант

Найпростіше не прибирати MongoDB, а використати дві СУБД в одному проєкті: MongoDB — для істот і геоданих, SQL Server через EF Core — для категорій, історичних нотаток або журналу дій.
